一、整体架构

这是一个什么系统？

✅ 离线镜像网站 + 后台管理系统

  • 从 www.4989028.com 抓取的原始页面 → 存本地 → 服务端期号偏移 → 渲染给用户

三、admin/server.js 核心逻辑

这个文件是整个系统的大脑，负责：

🔴 中间件（请求拦截）

  • 拦截所有 .html 请求
  • 读原始 HTML 文件
  • 调用 replaceIssueNos() 期号偏移
  • 替换图片 URL 中的期号
  • 返回渲染后的 HTML

🔵 API 接口

  • POST /api/admin/draw → 开奖
  • GET /api/kj → 查询开奖数据
  • POST /api/admin/content/auto-update → 生成资料
  • GET /api/admin/content → 读资料
  • GET /api/admin/history → 历史记录
// 启动时自动： // 1. 从 data.json 读 latest (最高期号) // 2. 从 content.json 读资料 // 3. 计算 offset = latest - 原始HTML最高期号 // 4. 定时检查（已停用），防止外部覆盖

四、为什么更改开奖期数后资料会变？

🔍 关键：期号偏移 (Issue Offset)

// replaceIssueNos() 函数逻辑: var origMax = 317; // 扫描原始 HTML 中所有独立的 "X期" 格式，取最大值 var curMax = 328; // 读取 data.json 中 history 的最高期号 var offset = curMax - origMax; // = 11 // 然后扫描整个 HTML，把每个期号都 +11 // 317期 → 328期 (开奖主期) // 316期 → 327期 (上一期) // 315期 → 326期 ... // 图片URL中的 (317) → (328) 等

所以 你改后台开奖期数 → latest 变了 → offset 变了 → 渲染时 HTML 里的所有期号跟着偏移

原始 HTML 里"停留在 317 期"的资料文字，被自动偏移成了 328 期的样子。

六、content.json 资料为什么没显示？

时间点发生了什么
之前我写了 renderSectionsIntoHtml() 函数，扫描 HTML 所有栏目前插入 nextQ 期生肖
后来你说"新增的资料集中在开奖框下面了，不是相同的资料" → 我重写了逐栏目插入
最后你说"资料不用添加了，因为不是相同的资料，而且生成的不对" → 我删了调用
现在中间件只做期号偏移，content.json 虽然有数据但不再注入 HTML

当前 content.json 状态：

  • 14 个栏目：content_wucuo / content_jinshu / content_sanxiao ...
  • 最高有到 330 期 的生肖数据（后台自动生成的）
  • 但页面只显示原始 HTML + 期号偏移，不读取这些生肖

十、系统特点总结

✅ 优点

  • 纯本地，不依赖外部接口
  • 期号自动偏移，改一次后台全站同步
  • 开奖自动生成下一期资料
  • 删除开奖记录自动回退 latest
  • 重复期号/数字前后端双重校验

⚠️ 限制

  • 图片不会自动生成（需手动放每期图）
  • content.json 有生肖数据但不注入页面
  • 原始 HTML 是 317 期旧版，偏移只是"换数字"
  • 外部定时抓取已停用（曾覆盖 latest）

🎯 核心原理 = 离线镜像 + 服务端期号偏移 + 后台数据管理
